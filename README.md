# SimIme —— 拟人化中文输入器

一个常驻托盘的 Windows 小工具：你在它的界面里粘贴一段中文，确认后它退到后台，
你切到目标窗口按 **F9** 二次确认，它锁定你的插入点，然后像人一样逐字打出来——
带随机快慢、思考停顿、偶发错字再退格改回，最后把热键注销进入静默待机，只留托盘可唤醒。

- 运行环境：Windows + .NET Framework 4.8（Win10/Win11 自带），无需安装、无需管理员权限。
- 交付物：单文件 `dist\SimIme.exe`（拼音表等资源已内嵌），可选 `dist\SimIme.Engine.dll`（引擎，供测试/集成）。
- 不注册系统输入法：拼音转汉字完全由程序内部决定，不影响你系统里已有的输入法。

### 1.1 词组级输入法工作流（默认）

**默认行为**：拼音**只在悬浮条内组串**，目标窗口**只收到词组级的汉字提交**——不会看到一串拼音被敲进去又退格。

**一次输入的过程**（以「天上有十二个」为例）：

1. 引擎把文本切成**词组块**（`EngineFactory.SplitPhrases`，实测：「天上有十二个」→ `天上 / 有十二个`；「我们明天去公园散步吧」→ `我们 / 明天 / 去 / 公园 / 散步 / 吧`）。
2. 取 1~3 个块组成**组串缓冲**，悬浮条上行显示这整段拼音，例如 `tianshangyoushierge`。
3. **按块从左到右确认**：每确认一块，就把该块的汉字提交到目标窗口，悬浮条上这一块**变灰**、剩余部分继续显示拼音。
4. 缓冲清空后继续下一组，直到整段文本打完。

**两类随机错误**（拟人化的一部分）：

- **词组整块同音错词**：如 `星星 → 猩猩`，随后**退格整块重打**成正确的词（默认概率 `Engine.Typo.WordHomophonePct = 2`）。
- **键盘相邻键错拼**：把拼音里某个字母打成**相邻键**，如 `xingxing → xingximg`（实测另例：`zhongguo → zhonggjo`）。默认**只在悬浮条里显示错拼再改正**，不会真的往目标敲错字母；只有把 `Inject.PinyinInTarget` 设为 `true` 才会连错字母一起打进目标再退格改正（默认概率 `Engine.Typo.KeyboardSlipPct = 3`）。

**粒度取舍（重要）**：词表是 **jieba 语料（实测 `common_words.tsv` 有 120000 行、都是 1~4 字词）**。切分规则是
「**以该字开头的最长词典词（2~4 字）优先；词典里查不到时，按种子抖动 1~4 字**」。

因此**同一句话在不同次运行可能给出不同粒度**：默认 `Engine.RandomSeed = 0` 表示每次运行都重新随机；
给一个非 0 的 `RandomSeed` 则完全可复现。实测「天上有十二个星星」（`SplitPhrases` 直接调用）：

- `RandomSeed=0` 第 1 次：`天上 / 有 / 十二 / 个 / 星星`
- `RandomSeed=0` 第 2 次：`天上 / 有 / 十二 / 个星星`
- `RandomSeed=0` 第 3 次：`天上 / 有 / 十二个 / 星星`
- `RandomSeed=12345` 两次（完全一致）：`天上 / 有 / 十二 / 个星 / 星`

所以**本文档里出现的切分例子只是「其中一次运行」的结果，不是唯一答案**；词典外的搭配（生僻字、新词）同样会被切细或按抖动合并。
**缓冲层显示的拼音串始终是完整的**（这正是悬浮条上能看到 `tianshangyoushierge` 这种整段拼音的原因）；
想把某个搭配稳定地整块提交，有两条路：**往词表里加词**（数据改动），或者**让程序自己学会**——它会把 2~4 字的连续片段计数，达到 `Engine.UserWordMinCount`（默认 3）次之后该词组也会优先整块（见 1.3）。

**启动日志里能看到当前生效的这套参数**：

```
词组工作流：切分实现=EngineFactory.SplitPhrases｜错拼实现=EngineFactory.MakeKeyboardSlip｜拼音字母入目标=否｜字母节奏=110ms｜块内字间隔=25ms｜相邻键错拼概率=3%
```

### 1.2 可选：让拼音字母真的进目标窗口（不推荐）

把 `Inject.PinyinInTarget` 设为 `true`，拼音字母才会真的敲进目标窗口再退格清掉；把 `Inject.ImeSimulation` 设为 `true` 则回到
「逐字 拼音 → 停顿 → 退格 → 汉字」的旧观感。**两者默认都是 `false`**，原因见下：

**注意：为什么默认关着**——在带**联想输入 / 增量搜索**的程序（某些搜索框、聊天输入框）里，退格可能
不足以清掉已键入的字母，会**残留字母并弹出联想候选**。本项目的最高优先级是「落屏文本 === 原文」，
所以这两个开关默认关闭；除非你确实想要那种效果，否则不要打开。

### 1.3 用户词表（自学习）

**学什么**：程序把你每次输入的**原文**里的 **2~4 字连续片段**计数，存进 exe 同目录的 `habits.dat`；
出现次数达到 **`Engine.UserWordMinCount`（默认 3）** 的词组，之后在切分时会**优先整块**提交。
例：常打「天上有」之后，`天上有` 会整块落下，不再被切成 `天上 / 有`（引擎对 2 次的片段先建暂存、第 2 次才升级为词组，参与切分仍以阈值 3 为准）。

**开关**：`Behavior.LearnUserWords`（默认 `true`）。关掉则**本次既不学习也不写盘**，日志里会明说。

**存储与重置**：`habits.dat`（完整路径会打印在 `--words` 输出与启动日志里）；**删掉该文件即重置学习**。
词组条目上限 **5000 条**，超出时按出现次数淘汰最少的（引擎侧 `MaxPhraseKinds`）。

**怎么看它在学**：

1. **启动日志**里有一行（实测原文）：
   ```
   用户词表：已学习 N 个用户词组（2~4 字）；词频表条目 M 个（例：天上有×5…）｜来源=…｜路径=…｜学习开关=开
   ```
2. **双击 `看用户词表.cmd`**（等价纯英文名 `words.cmd`），或手敲 `SimIme.exe --words`；
3. 主界面「基本」页有一行只读显示：`用户词表：N 个用户词组`。

**实测证据（我在本机做的学习实验）**：把同一句原文喂给习惯库 3 次后：

- `habits.dat` 从无到有（1274 字节）；`UserWordCount("天上有") = 3`；`--words` 报 `来源=EngineFactory.UserWords`，列出 45 个 ≥2 次的词组与次数；
- 切分对比：**不含**用户词时那一句切成 `我们 / 明天 / 去 / 公园 / 散步 / 天上 / 有十 / 二个 / 星星`（每次抖动还不一样），**含**用户词时 `天上有` **作为一个整块**出现：`我们明 / 天去公 / 园散步 / 天上有 / 十二个 / 星星`。

> 注意：自学习只影响**切分粒度**（哪几个字一起落下），不改变最终落屏文本——落屏仍然恒等于原文。

### 1.4 选词流程（同音词候选）

**候选是「词」不是「字」**：对当前待确认的那段拼音，程序从**三合一词表**（内置 12 万 + 外部 `dict_extra.tsv` + 用户习惯库）里找**同音词**，
按频次降序排列，并且**目标词恒排第一**。启动时会打印索引规模，格式如下（两个真实样本）：

```
# 真机（已装外部词表 46111 条）
候选词索引：142673 个词 / 105216 个拼音段（去重合并 23438 条：内置 …｜外部 …｜用户 … 条原始记录），建索引用时 163ms，拼音表=…
# 本机复现（只用内置表，未加载外部词表）
候选词索引：120000 个词 / 86511 个拼音段（去重合并 0 条：内置 120000｜外部 0｜用户 0 条原始记录），建索引用时 127ms，拼音表=PinyinTable
```

**真实同音词不足时用「同音字组合」补齐**到 `Inject.CandidateMax`（默认 6）：补齐项排在真实词之后，数据上带 `Generated` 标记（界面不区分显示）。
实测四组（前括号里是频次，标 `(生成)` 的是同音字凑出来的）：

```
yige     -> 1.一个(142747) 2.亿个(40) 3.以个(生成) 4.已个(生成) 5.意个(生成) 6.义个(生成)
hongse   -> 1.红色(4243) 2.洪色(生成) 3.宏色(生成) 4.鸿色(生成) 5.轰色(生成) 6.哄色(生成)
pingguo  -> 1.苹果(1334) 2.平果(生成) 3.评果(生成) 4.凭果(生成) 5.瓶果(生成) 6.屏果(生成)
xingxing -> 1.星星(398) 2.行星(703) 3.行刑(292) 4.悻悻(121) 5.猩猩(108) 6.星形(48)   ← 6 个全是真实同音词，没有生成项
```

> 次序只由**频次**决定，而频次来自当时加载了哪些表（内置 / 外部 / 用户），所以不同机器、装没装外部词表，第 2 名之后的次序可能不同；
> 不变的是：**目标词第一、真实词在前、生成项在后**。

**组串行是「已确认汉字 + 未确认拼音」混排**，当前段蓝色加粗带下划线。实测三帧（原文「一个红色苹果」）：

```
yige|hongsepingguo   ->   一个|hongse|pingguo   ->   一个红色|pingguo   ->   一个红色苹果（整行纯汉字）
```

**选定动作看得见**：被选中的候选会短暂高亮（浅蓝底 + 加粗），时长 `Inject.SelectHighlightMs`（默认 220ms），模拟你按空格/数字选词那一下。

**确认过程完全不碰目标窗口**：只有当一个「组串缓冲」全部确认完，才**一次性**把这段汉字注入目标窗口。
缓冲上限 `Inject.BufferMaxPhrases`（默认 3 个词组；设 1 = 逐词落字，调大 = 一口气落更多）。
日志里能看到这一行：

```
缓冲确认完毕，开始注入：第 1~3 段（上限 3 段/缓冲）
```
## 2. 快速开始

1. 把 `dist\SimIme.exe` 放到任意可写目录（例如 `D:\Tools\SimIme\`）。
2. 双击运行。**不会出现任务栏按钮**，只在通知区域（托盘）出现一个 SimIme 图标，鼠标悬浮显示当前状态。
3. 双击托盘图标（或右键 →「唤醒 / 显示主界面」）打开主界面，粘贴要打的文本，点「确认开始」。
4. 界面隐藏后，切到目标窗口（记事本、微信、Chrome…），把光标放到要输入的位置。
5. 按 **F9** 二次确认 → 程序倒计时/等待后开始逐字上屏。
6. 想中止按 **F12**；打完后自动进入静默待机，热键失效，双击托盘唤醒后热键才恢复。
7. 退出：托盘右键 →「退出 SimIme」。

### 2.1 双击即可用的脚本（dist 目录里）

不想记命令行参数就用这两个 `.cmd`，**双击即可**：

| 脚本 | 作用 |
|---|---|
| `看悬浮条外观.cmd`（等价纯英文名副本 `bartest.cmd`） | 双击后展示**真实运行时**的悬浮条外观 10 秒（`--bartest 10`，纯展示、不注入任何字符），结束后把详情打印在窗口里 |
| `看用户词表.cmd`（等价纯英文名副本 `words.cmd`） | 双击查看程序**从你输入习惯里学到的词组**（运行 `--words`，先说明用途与「删掉 `habits.dat` 即重置」，再回显 `selftest.log`） |
`更新词典.cmd`（等价纯英文名副本 `update-dict.cmd`） | 双击**联网更新内置词表并重建**（先跑 `tools\fetch_dict.ps1` 再跑 `build.ps1`）；必须先退出 SimIme，且必须在**项目目录的 dist** 里运行。日常补词请用主界面「联网更新词典」按钮，不要用这个 |
| `看排障样例.cmd` | 双击后展示 `--bartest-all 10`：只有 `Behavior.BarVerbose=true` **排障模式**才会出现的样例（停顿/换行/已暂停/锁定等待/进度数字），**默认运行时不会出现**；排障与截图用这个 |
| `自检落屏.cmd`（等价纯英文名副本 `verify-ime.cmd`） | **双击就能跑落屏自检**：先给你 **6 秒**去点中目标窗口（例如记事本），然后执行 `--verify "记事本"`，脚本会**自动依次尝试三个标题片段**：`记事本` → `Notepad` → `文本`（先中文后英文，命中即停；只有「没找到窗口」才会换下一个，若返回「目标不是前台」不会换片段重试）。找到后按「0=一致 / 2=不是前台 / 3=找不到窗口 / 4=缺参数 / 5=不一致 / 9=异常」对照打印退出码，并回显 `selftest.log`。**这是验证「落屏 === 原文」最省事的方式**；若你的编辑程序标题与这三个都不同（把鼠标悬停在任务栏图标上可看到标题，可能是英文），请按 4.1 手敲 `SimIme.exe --verify "你的标题片段"` |
| `权限自检.cmd` | 双击后跑 `--iltest`（只读诊断），打印「自身权限 / 前台窗口权限 / 结论：会不会被 UIPI 拦截」 |

- 这些脚本都用 `%~dp0` 定位同目录的 `SimIme.exe`（其中 `自检落屏.cmd` 内含 6 秒倒计时：`timeout /t 6 /nobreak`，若输入被重定向则自动用 `ping` 兜底等待），所以**必须与 SimIme.exe 放在同一个文件夹**；找不到会打印中文提示并等待按键。
- GUI 程序的 stdout 在 cmd 里可能看不到，因此脚本**运行完会读取同目录的 `selftest.log` 再显示**，保证双击后一定看得见内容。
- 三个 .cmd 都由 `build.ps1` 的**阶段四**自动生成（每次构建后一定是最新版本），不需要手工维护。
- 脚本里的中文提示按系统 OEM 代码页写入（CRLF 换行）；万一在非中文 Windows 上提示显示为乱码，也不影响日志内容的显示。

| F9 | `0x78`(120) | 二次确认 / 开始输入 |
| F8 | `0x77`(119) | 点击定位：用鼠标点目标输入框重新锚定 |
| F12 | `0x7B`(123) | 停止 / 进入静默待机（被占用时按候选顺序自动换键） |

托盘菜单：**唤醒 / 显示主界面**、**进入静默待机**、**退出 SimIme**；双击图标等同唤醒。
停止键有**候选回退**：首选 `Hotkeys.StopKey`（F12）；若被别的程序占用，会按 `Hotkeys.StopKeyCandidates`

想固定用别的键，改 `config.json` 的 `Hotkeys` 即可。

## 4. 命令行自检模式

```powershell
# 1) 打印当前生效配置，并在 exe 同目录写出 config.json
.\SimIme.exe --printconfig

# 2) 端到端自检：先在屏幕上打开一个目标窗口（如记事本），然后：
.\SimIme.exe --selftest "记事本"
# 也支持等号写法：  .\SimIme.exe --selftest=记事本
```

- `--selftest` 会查找标题含该片段的可见顶层窗口，走一遍「锚定 → 生成计划 → 注入」，
  结果同时打印到控制台并写入 exe 同目录的 `selftest.log`。
- exe 是 GUI 程序（winexe），若在 PowerShell 里看不到输出，程序会尝试附着到父控制台；
  实在看不到就直接看 `selftest.log`。
- 找不到目标窗口时它会提示「请手动点一下目标窗口后重新运行 --selftest」。
- `--iltest`：**只读权限自检**，不注入任何字符。比对本程序与前台窗口的权限级别，直接给出
  「会不会被 Windows UIPI 拦截」的结论（双击 `权限自检.cmd` 即可，不必手敲命令）。
- `--bartest [秒数]`：**纯外观展示，不注入任何字符**，每 1.5 秒轮换一个样例（不给秒数默认 8 秒，可给 1~600）。
  它展示的就是**真实运行时悬浮条的全部样子**：①汉字输入（上行：已输入拼音灰色 + 当前音节蓝色加粗带下划线；
  下行带序号候选，当前字浅蓝高亮）②纠错时拼音串变短。**停顿/换行/已暂停/锁定等待/进度数字/Reason 状态词
  在真实运行时不会出现在悬浮条上**——它们走托盘气泡 + 主界面状态区 + 日志。
- `--bartest-all [秒数]`：同上，但展示的是 `Behavior.BarVerbose = true` **排障模式**才有的样例
  （停顿/换行/已暂停/锁定等待/进度数字），排障或做文档截图时用这个。
  两个命令都可以用 PrintWindow 截图留档（`_verify\bar-own-*.png` 即开发期截图）。
- `--verify "标题片段" [测试文本]`：**注入后回读目标窗口内容并逐字比对**，退出码 0 就代表「落屏 === 原文」。
  这是最强的一条自动验证，详见 4.1。

### 4.1 `--verify`：注入后回读比对（端到端验证「落屏文本 === 原文」）

```powershell
SimIme.exe --verify "记事本"                     # 不给文本则用内置样例
SimIme.exe --verify "记事本" "自定义测试文本"     # 位置参数：第二个参数是测试文本
```

**前提**：目标窗口必须是**当前前台**窗口。不是前台时程序**拒绝注入**（绝不盲目往不确定的窗口打字）；
全程不调用 `SetForegroundWindow`、不弹任何对话框；本模式**强制直投**（不使用字母预览 / `Inject.ImeSimulation`）。

**它做什么**：把测试文本打进前台匹配窗口 → **回读该窗口内容** → 逐字比对 → 结论写入 `selftest.log` 与 `error.log`。

| 退出码 | 含义 |
|---|---|
| 0 | 结果一致（落屏 === 原文） |
| 2 | 目标窗口不是当前前台窗口（已拒绝注入） |
| 3 | 没找到标题匹配的可见窗口 |
| 4 | 缺参数（没给标题片段） |
| 5 | 注入失败 / 中途失焦 / 落屏与原文不一致 |
| **6** | **完整性护栏命中**：我方完整性低于目标，或读取目标完整性被拒（win32=5）——按键会被 Windows 丢弃，直接中止并提示改用 `SimIme-Admin.exe` |
| 9 | 异常 |

**为什么单独给 6**：跨完整性时 `SendInput` 会被 Windows **静默丢弃却仍返回成功**，若不设这道护栏，
就会把 UIPI 丢键误报成「落屏不一致」。所以它宁可提前中止，也不给一个误导人的比对结论。

**回读方式**：三条路径按顺序尝试，每一步的结果都会写进日志。

1. **焦点控件 + 经典文本类名 → `WM_GETTEXT`**：先定位目标窗口里的焦点控件，只有类名属于经典文本控件才用它
   （`EDIT` / `RICHEDIT` 前缀，或类名含 `.EDIT.` / `.RICHEDIT`，例如 WinForms 的 `WindowsForms10.EDIT.app.0.xxx`）；
   `SendMessageTimeout` + `SMTO_ABORTIFHUNG`，跨进程由系统编组、无副作用。
2. **UIA → `ValuePattern` / `TextPattern.DocumentRange.GetText`**：面向现代控件（Win11 记事本 / UWP / WPF / Chromium），
   带超时并跑在后台线程上（超时即降级，不会把程序卡住）。
3. **剪贴板 `Ctrl+A` / `Ctrl+C`**：最后兜底，**必定会真的尝试**；先用哨兵串占位，以区分「复制是否真的发生」，
   **结束时无条件还原你原来的剪贴板**。

> **决定性护栏**：每一步读回来的文本都必须**非空、且不等于目标窗口的标题**，才会被采用；否则自动换下一条路径。
> 这条护栏专治「把窗口标题当成正文」那类误报——顶层窗口的 `WM_GETTEXT` 返回的本来就是这个标题。
> 三条路径都拿不到有效文本时，结论里会写明 `三条路径都未取到有效文本`，**不会给你一个假的「不一致」**。

**日志怎么读**：每次回读都会留下这样一行（`selftest.log` 与 `error.log` 都有）：

```
回读方式=<方法>｜读回长度=N｜有效=True
```

`<方法>` 是下面三种之一：`WM_GETTEXT(焦点控件 class=Edit)`、`UIA(TextPattern)`、`剪贴板(Ctrl+A/Ctrl+C)`。
某条路径试过但没被采用时，还会看到 `… 结果不可用（空值或等于窗口标题），转下一路径；长度=N` 或
`焦点控件 class=… 不是经典文本控件，跳过 WM_GETTEXT` 这类行——从它就能看出为什么换了路径。

**结论行怎么读**：

```
结果=一致｜预期字符数=N｜实际字符数=M
```

不一致时另给：**首个不同位置（0 基）**、预期片段、实际片段、类型（少字 / 多字 / **疑似拼音字母残留**）。
「疑似拼音字母残留」就是 1.1 节说的字母预览残留，遇到它请先确认 `Inject.ImeSimulation` 是 `false`。

### 4.2 更新词典：两条路径（别混淆）

词典分两层：**内置基线**（打包进 exe 的 `common_words.tsv`，12 万条）与**外部词表**（exe 同目录的 `dict_extra.tsv`）。
两条更新路径作用点不同：

| 路径 | 什么时候用 | 做了什么 | 需要重建？ | 需要管理员？ |
|---|---|---|---|---|
| **程序内「联网更新词典」按钮**（推荐，日常用） | 想补常用词 / 跟进上游词表 | 从 `Behavior.DictMirror` 镜像下载，写到 exe 同目录的**外部词表** `dict_extra.tsv`，启动时叠加进词组词典（新词立即参与切分） | **不需要** | 不需要 |
| **`更新词典.cmd`**（维护 / 高级用） | 要把**内置基线整体换代** | 跑 `tools\fetch_dict.ps1` 重新生成 `src\Assets\common_words.tsv`，再**重新构建** exe（因为词表是内嵌的） | **必须** | 不需要，但需要项目源码目录 + PowerShell 7 |

> **重建不会动你的用户数据**：config.json（你的设置）、habits.dat（自学习记录）、habits.version（学习库算法版本标记）、habits_merges.tsv（相邻块搭配的学习记录）、dict_extra.tsv（已下载的外部词表）在构建时会被**先移出 dist、构建完成原样放回**；构建失败也一样放回，不会丢。
> **这些文件缺任意一个都可能导致学习记录被清空或丢失**——尤其是 habits.version：程序会在两处读它（exe 同目录的 habits.version 与 `%APPDATA%\SimIme\learning.version`）取最大值，任一处够新就不清空；两处都缺而 habits.dat 还在时，才把 habits.dat 与 habits_merges.tsv 当作旧算法学习库清空（用来丢弃旧算法产出的碎片词）。
> 在构建时会被**先移出 dist、构建完成原样放回**；构建失败也一样放回，不会丢。

- 命令行等价入口：`SimIme.exe --updatedict [--mirror URL] [--dictout PATH]`。
- 外部词表路径可改：`Behavior.ExtraDictFile`（留空 = exe 同目录 `dict_extra.tsv`）；镜像可改：`Behavior.DictMirror`（默认 `http://mirrors.aliyun.com/pypi/simple/`，**本机 HTTPS 不通时务必用 http**）。
- 外部词表是否已安装：看 `--words` 输出或启动日志里的「外部词表」一行。
#### 外部词表到底是什么（**必须知道**）

按钮下载的是 pypinyin 的 `phrases_dict.json` —— 这是**「注音消歧词表」，不是通用词表**：它只收录「读音需要特判」的词。
实测用户真机产出的 `dict_extra.tsv`（**690963 字节 / 46111 行**）：

| 词 | 外部表里有吗 | 说明 |
|---|---|---|
| `十二个` / `我们` / `散步` / `你好` | **有** | 读音需要特判，属于消歧词 |
| `星星` / `太阳` / `明天` / `但是` / `生日快乐` / `天上有` | **没有** | 逐字默认读音就正确，不需要特判 |

所以它是**补充，不能替换内置词表**：内置表里 `星星(398)`、`太阳(5044)`、`明天(3264)`、`但是(28055)` 这些常用词都在，
若拿外部表去替换，词组切分会**退化**。

两条路径的语义也因此不同：

- **程序内按钮＝叠加**：内置表当地基、外部表只做增补，永远安全、**不会丢词**。优先级：**用户词组 > 外部词表 > 内置表**。
  用户真机实测：**36.7 秒**下载 840203 字节 → 解出 **46111 条** → `SetExtraWordFile` 注册成功 → **本次运行即生效**。
- **`更新词典.cmd`＝默认合并**（`-Mode auto`，默认源也已换成同一个 pypinyin 轮子）：
  pypinyin 源 → **merge**（与现有 `src\Assets\common_words.tsv` 求并集、同名取较大频次、仍按上限截断）；`-Source jieba` → replace。
  实测以真实表为基合并：baseRows=120000 + addRows=46111 → mergedDistinct=142673 → 按上限写出 **120000 行 / 1574205 字节**，
  抽检 `星星`/`太阳`/`明天`/`但是` **全部保留**，并吸收约 **2.27 万条**消歧词组。
  **默认是合并，不会丢词；`-Mode replace` 只在你明确要精简表时才用。**

#### `更新词典.cmd` 的前置条件与失败时你会看到什么

它必须**放在项目目录的 dist 里双击**（靠 `%~dp0..` 找项目）。任何一步失败都会**明确告诉你当前状态**，不用猜：

| 情况 | 你会看到的输出 | 退出码 | 当时的状态 |
|---|---|---|---|
| 不在项目目录内（缺 `..\tools\fetch_dict.ps1` / `..\build.ps1` / `..\src\Assets`） | 「本脚本必须放在项目目录的 dist 里运行」+ 实际检查的上级目录 | **2** | 词表未改动、程序未重建，什么都没发生 |
| 有 `SimIme.exe` 在运行 | 「检测到 SimIme.exe 正在运行…请先退出（托盘右键退出或任务管理器结束），否则重新构建会失败」 | **3** | 同上，什么都没发生 |
| 拉表失败（镜像不可达 / 网络被拦） | 「词表未更新（原因见上），现有词表与程序未被修改」 | **4** | 旧词表保留、exe 未重建（不会继续构建） |
| 拉表成功但重建失败 | 「词表已更新但重建失败，请把上面的输出发给开发者」 | **5** | 词表**已换新**，但 exe 没重建成功 |
| 找不到 pwsh / `%TEMP%` 为空 | 对应中文说明 | 6 / 7 | 什么都没发生 |

> 设计说明：重建会**清空 dist**，而这个脚本自己就住在 dist 里，所以它先把自身复制到 `%TEMP%` 再执行重建——
> 否则重建清空 dist 时会把正在运行的脚本自己删掉。

全部成功时会打印：**新版词表行数 / 字节数**、**新版 `SimIme.exe` 字节数与 SHA256**，以及「已生效：下次启动即使用新词典」。


### 4.3 `--notify`：系统通知（不弹窗、不抢焦点）

**用途**：需要提醒你、但**不该弹前台对话框也不该抢焦点**的场合——例如长任务处理完了叫你回来看一眼。

```powershell
SimIme.exe --notify "标题" "正文"
```

**两条通道**：

1. **托盘气泡**（主通道）：`NotifyIcon.ShowBalloonTip`，默认 **6000ms**，调用后还会等 2500ms 让气泡有机会显示完毕；
2. **Windows 通知中心 Toast**（尽力而为）：经 `%SystemRoot%\System32\WindowsPowerShell\v1.0\powershell.exe` 调 WinRT 的 `ToastNotificationManager`。
   普通桌面进程**没有包标识**，本机实测**必然失败**（`0x80073D54`）；失败**只写日志、不影响退出码**。

| 退出码 | 含义 |
|---|---|
| 0 | 至少一条通道成功 |
| 2 | 两条都失败 |
| 1 | 参数缺失（会打印用法） |

**真实输出样本**（`error.log`，一次实测；我本机复跑也是同样三行）：

```
--notify 托盘气泡：成功｜已调用 ShowBalloonTip(6000ms) 并等待 2500ms，图标已创建
--notify Windows Toast：失败｜powershell 退出码=1｜无输出文件内容
--notify 完成，退出码=0
```

> **Toast 失败属预期**，不代表通知没发出去——**以托盘气泡为准**。

## 5. 权限（管理员）

**一句话**：你现在用的账号能不能「碰」到目标窗口，决定了能不能往里打字。

- **普通身份运行**：绝大多数程序（记事本、微信、浏览器、Office）都能正常注入。
- **打不进高权限窗口**：如果目标窗口是**以管理员身份运行**的（以管理员身份打开的编辑器、
  任务管理器、部分安装程序/游戏），Windows 有一条安全规则（UIPI）**禁止**低权限进程向高权限窗口
  发送按键。这不是本程序的 bug——任何模拟按键的软件都受这条规则约束。
- **怎么解决**：双击 `SimIme-Admin.exe`（与 SimIme.exe 放在同一目录）→ 弹**一次** UAC → 同意后
  启动的就是「管理员版 SimIme」，此时可以注入管理员窗口。主程序 `SimIme.exe` **故意不提权**，
  这样日常启动不会每次都弹 UAC；只有真的需要写管理员窗口时，才用启动器。
- **怎么知道当前是什么身份**：主界面常驻一行「权限：…」（普通用户 / 以管理员身份运行）；
  启动时也会把 版本/构建时间/是否管理员/操作系统/运行时/系统 DPI/目录 写进 `error.log` 的「启动诊断」。
- **关于 SmartScreen**：本程序**不带 MOTW**（已核验 `Zone.Identifier` 不存在），自己编译出来的产物
  不会触发「Windows 已保护你的电脑」。若你看到该提示，说明这份副本是从别处拷来的、自带区域标记，
  点「更多信息 → 仍要运行」即可。
- **更省一步的做法**：不想用启动器时，可以**右键 `SimIme.exe` →「以管理员身份运行」**；
  实测这比经启动器**少一次中间环节**（启动器的价值是提供一个「每次都提权」的固定入口）。
- **被拒绝时会怎样**：`error.log` 会写明「目标窗口可能以管理员权限运行，Windows 拒绝跨权限注入」，
  并给出两条出路：改用 `SimIme-Admin.exe`，或把 `Inject.Method` 设为 `Clipboard` /
  保持 `Inject.ClipboardFallback=true` 走剪贴板兜底。

### 5.1 用 `_verify\typetest.exe` 做权限对照实验（最直观）

`typetest.exe` 只做一件事：等 **8 秒**后把 `测试ABC123` 打进**当时的前台窗口**，并把
「自身权限 / 目标窗口权限级别 / SendInput 返回值与错误码」写进同目录的 `typetest-result.txt`。

| 步骤 | A：正常双击（普通身份） | B：以管理员身份运行 |
|---|---|---|
| 1 | 打开记事本，点进编辑区 | 同左 |
| 2 | 双击 `_verify\typetest.exe` | 右键 `_verify\typetest.exe` →「以管理员身份运行」 |
| 3 | 8 秒内点一下记事本编辑区，保持它在前台 | 同左 |
| 4 | 看记事本是否出现 `测试ABC123`，并读 `typetest-result.txt` | 同左，两份结果做对比 |

- A 失败、B 成功 → 你遇到的正是 UIPI 权限问题：以后遇到高权限目标窗口就用 `SimIme-Admin.exe`。
- B 也失败 → 不是权限问题，看 `typetest-result.txt` 里的 SendInput 返回值/错误码。

## 7. config.json 字段含义

位置：**exe 同目录**的 `config.json`（不存在时用内置默认值；`--printconfig` 会生成/覆盖它）。
下面字段名与默认值来自程序实测输出（`--printconfig`）。

```json
{
  "Hotkeys": { "StartKey": 120, "LocateKey": 119, "StopKey": 123, "StopKeyCandidates": [123, 121, 122, 117, 118] },
  "Inject":  { "Method": "SendInput", "ClipboardFallback": true, "RestoreClipboard": true, "ClipboardPasteDelayMs": 150, "ImeSimulation": false, "ImePreviewMs": 200, "PinyinInTarget": false, "PinyinLetterMs": 110, "CommitCharMs": 25, "CandidateMax": 6, "SelectHighlightMs": 220, "BufferMaxPhrases": 3 },
  "Anchor":  { "Method": "Auto", "UiaTimeoutMs": 800 },
  "Behavior":{ "ClickLocateCountdownMs": 3000, "FocusLostPolicy": "Pause", "LogEnabled": true, "BarOffsetX": 6, "BarOffsetY": 22, "BarVerbose": false, "LearnUserWords": true, "DictMirror": "http://mirrors.aliyun.com/pypi/simple/", "ExtraDictFile": "" },
  "Engine":  { "Rhythm": { "...": "见下" }, "Typo": { "Enabled": true, "WordHomophonePct": 2, "KeyboardSlipPct": 3, "...": "其余见下" }, "RandomSeed": 0, "UserWordMinCount": 3 }
}
```

### Hotkeys（虚拟键码，十进制）
| 字段 | 默认 | 含义 |
|---|---|---|
| `StartKey` | 120 (F9) | 二次确认/开始 |
| `LocateKey` | 119 (F8) | 点击定位 |
| `StopKey` | 123 (F12) | 停止/静默（首选键） |
| `StopKeyCandidates` | [123,121,122,117,118] | 停止键候选顺序 `F12,F10,F11,F6,F7`；`StopKey` 被占用时按此顺序回退，实际生效的键见 `error.log` 与主界面「热键：」 |

### Inject（上屏方式）
| 字段 | 默认 | 含义 |
|---|---|---|
| `Method` | `SendInput` | `SendInput`=键盘事件逐字注入；`Clipboard`=剪贴板分段粘贴 |
| `ClipboardFallback` | `true` | SendInput 被目标拒绝时自动转剪贴板兜底 |
| `RestoreClipboard` | `true` | 结束后还原你原来的剪贴板内容 |
| `ClipboardPasteDelayMs` | 150 | 每次粘贴后等待毫秒数 |
| `ImeSimulation` | **`false`** | **默认关闭**：直接上屏汉字。设 `true` 开启「字母预览」（先敲拼音字母→停顿→退格→再敲汉字，观感像真输入法）；**在带联想/增量搜索的输入框里字母可能残留并触发弹窗**，见 1.1 |
| `ImePreviewMs` | 200 | 上面那串拼音字母的停留时间（建议 120~300） |
| `PinyinInTarget` | **`false`** | **拼音字母是否真的敲进目标窗口**。默认 `false`＝只在悬浮条组串；设 `true` 会把字母打进目标再退格（部分程序可能残留字母） |
| `PinyinLetterMs` | 110 | 开启上面那项时的**字母节奏**（每个字母之间的毫秒数） |
| `CommitCharMs` | 25 | **块内字间隔**：一次提交一个词组块时，块内各汉字之间的毫秒数 |
| `CandidateMax` | 6 | 每段的候选数量（3~9）：真实同音词优先，不足时用同音字组合补齐 |
| `SelectHighlightMs` | 220 | 选中候选时的高亮停留时长（毫秒，模拟按空格/数字选词） |
| `BufferMaxPhrases` | 3 | 一个组串缓冲最多几个词组（1=确认一段就落一段；调大=整句一次落） |
| ~~`Inject.KeyboardSlipPct`~~ | — | **已废弃并从配置中移除**。唯一生效的是 `Engine.Typo.KeyboardSlipPct`（默认 3，启动日志里的「相邻键错拼概率」取自它）。若你的 `config.json` 里仍能看到 `Inject.KeyboardSlipPct`，说明用的是清理前的旧构建，改它没有任何效果 |

### Anchor（锚定策略）
| 字段 | 默认 | 含义 |
|---|---|---|
| `Method` | `Auto` | `Auto`=三级兜底；也可固定 `Caret` / `Uia` / `Mouse` |
| `UiaTimeoutMs` | 800 | UIA 查询超时（超时自动降级，避免卡住） |

### Behavior（行为）
| 字段 | 默认 | 含义 |
|---|---|---|
| `ClickLocateCountdownMs` | 3000 | 点「点击定位」后的倒计时毫秒数 |
| `FocusLostPolicy` | `Pause` | 目标窗口失焦时：`Pause`=暂停等待 / `Abort`=中止收尾 |
| `LogEnabled` | **`true`** | **默认开启**运行期诊断日志（exe 同目录 `error.log`，超 2MB 轮转为 `error.log.1`）。改成 `false` 即不留痕 |
| `BarOffsetX` / `BarOffsetY` | 6 / 22 | 悬浮条相对插入点的像素偏移 |
| `LearnUserWords` | **`true`** | **用户词表自学习**开关：把每次输入的原文里的 2~4 字片段计数并写盘（`habits.dat`）；设 `false` 则本次不学习也不写盘（日志会说明）。详见 1.3 |
| `DictMirror` | `http://mirrors.aliyun.com/pypi/simple/` | 联网更新词典用的镜像（**HTTPS 不通时务必 http**） |
| `ExtraDictFile` | 空（= exe 同目录 `dict_extra.tsv`） | 外部词表路径；程序内「联网更新词典」按钮下载到这里，启动时叠加进词组词典（**不需重建**） |
| `BarVerbose` | `false` | 悬浮条详细状态开关。默认 `false`＝像真输入法（只显示拼音与候选，其余步骤不显示悬浮条）；排障时设 `true` 可看到停顿/等待/锁定等状态 |

### Engine.Rhythm（节奏）
| 字段 | 默认 | 含义 |
|---|---|---|
| `CharDelayMinMs` / `CharDelayMaxMs` | 90 / 260 | 每字基础延迟区间 |
| `SpeedVariancePct` | 35 | 速度方差百分比 |
| `BurstChancePct` | 12 | 突发连打概率 |
| `ThinkPauseMinMs` / `ThinkPauseMaxMs` | 500 / 2500 | 思考停顿时长区间 |
| `ThinkEveryMinChars` / `ThinkEveryMaxChars` | 8 / 20 | 每多少字插入一次思考停顿 |
| `RestPauseMinMs` / `RestPauseMaxMs` | 3000 / 8000 | 句子间休息时长区间 |
| `RestEveryMinSentences` / `RestEveryMaxSentences` | 2 / 5 | 每多少句休息一次 |
| `StartupDelayMs` | 1500 | F9 之后、开始打字前的启动等待（留给你把鼠标移开） |
| `PunctuationExtraMinMs` / `PunctuationExtraMaxMs` | 80 / 400 | 标点额外停顿区间 |

### Engine.Typo（错字）
| 字段 | 默认 | 含义 |
|---|---|---|
| `Enabled` | `true` | 总开关；关闭后按理想速度直打 |
| `HomophonePct` | 4 | 同音字错字概率 |
| `NasalPct` | 3 | 鼻音错字（前后鼻音混淆）概率 |
| `HeadRedoPct` | 15 | 句首重打概率 |
| `OmissionPct` | 2 | 漏字回填概率 |
| `RepeatWordPct` | 2 | 重复输入概率 |
| `MaxTyposPerSentence` | 2 | 每句最多错几次 |
| `WordHomophonePct` | 2 | **词组整块同音错词**概率（如 `星星→猩猩`，随后退格整块重打成正确的词） |
| `KeyboardSlipPct` | 3 | **相邻键错拼**概率（如 `xingxing→xingximg`）。默认只在悬浮条显示错拼再改正；要真的敲进目标需同时开 `Inject.PinyinInTarget` |

### Engine（其他）
| 字段 | 默认 | 含义 |
|---|---|---|
| `RandomSeed` | 0 | `0`=每次运行随机；非 0 时**同一 seed 产生完全相同的计划**（便于复现/测试）。注意它同时影响切分粒度（见 1.1/1.3） |
| `UserWordMinCount` | 3 | **用户词组参与切分的最低出现次数**：某 2~4 字片段出现次数达到它之后，切分时优先整块（见 1.3） |

### 日志与诊断（默认开启）

| 项目 | 说明 |
|---|---|
| 位置 | exe 同目录 `error.log`（崩溃兜底始终写盘） |
| 轮转 | 超过 2MB 自动轮转为 `error.log.1` |
| 启动诊断 | 版本、构建时间、是否管理员、操作系统、运行时、系统 DPI、程序目录 |
| 锚定 | 每次锚定所用的方法，以及 raw / converted 两套坐标与实际采用值 |
| UIA | 每次 TextPattern 尝试与其结果（含超时降级） |
| 注入 | 每个 Step 的 Kind / delay / 字符(拼音) / reason |
| 失败 | SendInput 被拒时记录返回值、`GetLastError` 与明确指引 |

不想留痕：把 `Behavior.LogEnabled` 改成 `false` 并重启程序。

> 提示：把 `Typo.Enabled` 设为 `false`、把 `Rhythm` 各项调小，就是「快速直打」模式，适合调试。

## 8. 已知限制

1. **前台窗口必须真实存在**：本工具靠 `GetForegroundWindow` 锁定目标；开发沙箱内无法取得前台窗口，
   所以「锁定→上屏」这一段只能由你在本机人工验收（第 6 节 A5–A12）。
2. **插入符不一定取得到**：部分程序（Chrome/Electron 网页、部分自绘控件）不暴露 Win32 caret，
   此时依次降级到 UIA TextPattern、再降级到鼠标位置；精度取决于目标程序对 UIA 的支持程度。
3. **UIA 的能力边界**：.NET Framework 4.8 的 UIA 客户端**没有** `TextPattern2`/`ITextProvider2`
   （实测 csc 报 CS0246/CS0117），因此本项目使用 `TextPattern.GetSelection()` +
   `TextPatternRange.GetBoundingRectangles()` 取得插入点矩形；`GetSelection()` 返回的是
   **`TextPatternRange[]` 数组**，取第一个元素即可。
4. **管理员权限窗口**：目标程序以管理员运行时，普通权限的 SimIme 无法向它注入输入（Windows UIPI 限制）。
   这是系统安全边界而不是缺陷，但有现成解法：用 `SimIme-Admin.exe` 以管理员身份启动主程序（见第 5 节）。
5. **单套 UIA 引用**：编译时只能引用一套 UIA 程序集（Reference Assemblies v4.8 **或** Framework64\WPF），
   同时引用两套会因同一标识重复而报 `CS1703`；`build.ps1` 已自动只挑一套并打印选中的路径。
6. **构建非字节级可复现**：csc 4.0 会写入模块 MVID 与 PE 时间戳，连续两次构建的 exe **尺寸一致**
   （实测同一轮内两次字节数完全相同、逐字节仅 46 字节不同），但 SHA256 不同。请以「尺寸 + 功能」而不是哈希比对构建结果。
7. **DPI 与清单**：未内置 DPI 感知清单与图标资源；若你需要，把 `app.manifest` / `app.ico` 放进 `src\App\`，
   `build.ps1` 会自动带上（`/win32manifest:`、`/win32icon:`）。
8. **源码编码规则**：所有 `.cs` 应保存为 **UTF-8 带 BOM**，编译固定追加 `/codepage:65001`。
   实测：即使漏了 BOM，只要带 `/codepage:65001` 中文字面量仍正确（`static_checks.ps1` 会以 WARN 提示补齐）。
9. **自检模式的测试侧缺口**：`tests\engine_tests.ps1` 通过 PowerShell 反射调用
   `EngineFactory.CreateHabitStore(string)` 时会受 PSObject 装箱限制而失败，因此该脚本里
   `BuildPlan` 收到的是 `null` 习惯库（引擎按默认词权重工作，6 条断言不受影响）；
   程序运行时（`src\App\TrayContext.cs`）传入的是真实 `IHabitStore`。
10. **拼音字母默认不进目标窗口**（`Inject.PinyinInTarget = false`，`Inject.ImeSimulation = false`）：默认只把汉字
    按词组块提交，字母仅在悬浮条内显示。若开启字母入目标，部分程序（带联想/增量搜索的输入框）里退格可能
    不足以清除已键入的字母，导致字母残留、弹出候选框，甚至弄脏落屏文本。本项目以「落屏文本 === 原文」为最高
    优先级，因此默认关闭；只有明确需要那种观感时才打开。

```powershell
# 一键构建（先清空 dist，再产出引擎库与主程序）
pwsh -NoProfile -File .\build.ps1        # 退出码：0=成功 1=编译失败 2=源码/资源未就绪（附清晰提示）
```

构建规则（`build.ps1` 自动完成）：
- 编译器固定 `C:\Windows\Microsoft.NET\Framework64\v4.0.30319\csc.exe`（C# 5），全部源码追加 `/codepage:65001`。
- 阶段一：`src\Engine\*.cs` → `dist\SimIme.Engine.dll`（`/target:library`，内嵌同一套资源，故可独立加载与测试）。
- 阶段二：`src\Engine\*.cs` + `src\App\*.cs` → `dist\SimIme.exe`（`/target:winexe`，单文件）。
- `src\Assets\*.tsv` 全部以 `SimIme.Assets.<文件名>` 为资源名内嵌（与 `src\Engine\PinyinTable.cs`、`CommonWordIndex.cs` 的 `ResourceName` 常量一一对应）。
- 引用：`System` / `System.Core` / `System.Drawing` / `System.Windows.Forms` / `System.Web.Extensions` +
  UIA 一套（`UIAutomationClient` / `UIAutomationTypes` / `UIAutomationProvider` / `WindowsBase`），
  优先 `Reference Assemblies v4.8`，缺失则回退 `Framework64\WPF`，并把选中路径打印出来。
- 阶段三：`src\Tools\AdminLauncher.cs` → `dist\SimIme-Admin.exe`（`/target:winexe`），
  并用 `/win32manifest:src\Tools\SimIme-Admin.manifest` 嵌入 **requireAdministrator** 清单，
  使它每次启动都会请求 UAC 提权（主程序 `SimIme.exe` 保持 asInvoker，不带该清单）。
  缺少 `src\Tools\*.cs` 或清单时会明确报错退出（退出码 2），不会静默跳过这一步。
- 清理 dist 前会把**用户数据**（config.json / habits.dat / habits.version / habits_merges.tsv / dict_extra.tsv）移到临时位置，
  构建成功或失败都原样放回（构建失败也不会丢）；这些文件不存在时不报错。
  **这些文件缺任意一个都可能导致学习记录被清空或丢失**：habits.version 记录学习库的算法版本，程序读 exe 同目录与 `%APPDATA%\SimIme\learning.version` 两处取最大值；两处都缺而 habits.dat 还在时，程序会把 habits.dat 与 habits_merges.tsv 当旧算法学习库清空。
  其中 **habits.version 记录了学习库的算法版本**：若它缺失而 habits.dat 还在，程序启动时会按「旧版学习库」把 habits.dat 与 habits_merges.tsv 一并清空——所以它必须跟 habits.dat 一起被保留。
- **动 dist 之前先预检**：检测到 SimIme 进程会先尝试结束它；**杀不掉就直接以退出码 3 拒绝构建并打印「dist 未被改动」**，绝不先删一半。
- 清理 dist 时**逐个文件处理**：删不掉的打印 `[警告] 跳过被占用的文件：<名>` 后继续，并尝试把它**同盘改名**为 `<名>.old-<时间戳>`（运行中的映像通常仍可改名）；改名成功时新文件能正常写入，旧文件留到「下次启动前可删除」。改名时若文件名已含 .old-，会**替换旧后缀**而不是叠加（不会出现 SimIme.exe.old-….old-…），且 dist 里这类 .old- 残留**只保留最近 1 份**，更早的会删除并打印 `[WARN] 已删除更早的 .old 残留：…`。
- 结束时校验三个主产物是否**真的被本次构建更新**：没更新就以退出码 4 报「部分产物未更新（被占用）：…」，**不会谎报构建成功**（编译期就失败则是退出码 1）。
- 10 个双击脚本在**编译之前**生成，所以即使编译失败，dist 里仍保有齐全的自检脚本（权限自检.cmd、自检落屏.cmd 等）。
- **构建顺序是「先编译到暂存、成功后才动 dist」**：三个产物先编译进 _devC\obj\stage，校验都非空后才执行「预检 → 移出用户数据 → 清理 dist → 搬入产物 → 生成脚本 → 收尾断言」。**任何编译失败都不会改动 dist**（旧产物原样保留），并明确打印「构建中止：dist 未被改动（仍是上一版产物）」。
- **构建失败绝不能破坏已交付的 dist**（铁律）：先编译到暂存目录、三个产物都校验通过才允许动 dist；五件用户数据原样放回并逐件校验、日志归档保留——细则见本节上文的构建规则与三个回归入口。
- **收尾断言**：构建结束时 dist\SimIme.exe、dist\SimIme.Engine.dll、dist\SimIme-Admin.exe 必须存在、非空、且被本次构建更新过；任一不满足就以退出码 4 打印「收尾断言失败：dist 产物不合格」并给出恢复指引，**绝不谎报成功**。
- **构建成功路径也必须把用户数据放回并逐件校验**：构建结束前会逐件核对五件用户数据是否真的回到 dist，缺任何一件即以**退出码 5** 失败（提示可从 _devC\obj\userdata-stash 手动复制回）。可用 `pwsh -NoProfile -File _devC\regress_userdata.ps1` 一条命令重跑三条回归（正常构建 / 编译失败 / 变异回归；脚本只在 _devC\regress 下工作，不写真实 dist）。
- **日志不会被删，只会归档**：构建前把 dist 里的 `error.log` / `selftest.log`（以及更早的 `*.log.old-*`）搬出暂存，构建后以 `error.log.old-<yyyyMMdd-HHmmss>` 放回 dist（同一秒冲突时追加 `-2`、`-3`…）；**每类只保留最近 3 份**，更早的会删除并打印告警。所以构建后要查上一轮运行的日志（错字时序、标点延时等），看 `dist\error.log.old-*`。可用 `pwsh -NoProfile -File _devC\regress_logs.ps1` 一条命令重跑日志归档回归（同样只在 _devC 下工作）。
- 阶段四：把双击即用的脚本写进 `dist\`（当前 10 个：`bartest.cmd`、`看悬浮条外观.cmd`、`看排障样例.cmd`、`权限自检.cmd`、`自检落屏.cmd`、`verify-ime.cmd`、`看用户词表.cmd`、`words.cmd`、`更新词典.cmd`、`update-dict.cmd`），
  文本按**系统 OEM 代码页 + CRLF**写入，双击即用；脚本用 `%~dp0` 定位同目录 exe，并在结束时回显 `selftest.log`。
- 成功时打印产物路径、字节数、SHA256、警告数、耗时；失败时打印完整编译器输出并 `exit 1`。

| 1 | 逐词断言破坏 | 第 N 段（'…'）注入完成后，落屏尾部/前缀与该段原文不符 |

| 3 | 块内停顿断言破坏 | 计划下标=i 的 Sleep 夹在同块两个 Char 之间、却仍在注入序列里执行 |
| 4 | 提交前悬浮条断言破坏 | 写入目标前 `_barStatus.Visible` / Composing 不为空 |
| 5 | 组串单位断言破坏 | 计划下标=i 落屏 'c'，但最近组串的单位是 'u' |
| 6 | 重复组串断言破坏 | 计划下标=i 已被单位 'u1' 覆盖，又被单位 'u2' 覆盖 |

#### 已知限制（运行期相关，另见第 8 节）

- 标点**直接上屏**、不经组串与候选（真输入法行为）；日志里有『标点直接上屏（不经组串）』一行
- F12 被其它软件占用时，停止键会**自动兜底**（候选顺序见 `config.json` 的 `StopKeyCandidates`）
- 新版 Windows 记事本（带格式工具栏）在部分字体下会把注入的中文画成**方框**；这是记事本的字形回退问题，**不是注入内容错误**（用 Ctrl+A/Ctrl+C 粘出来看，或看窗口标题栏即可确认内容正确）
- 权限：普通权限运行时，对管理员窗口的注入会被 **UIPI 静默丢弃**（`--iltest` 可查）；需要时用管理员启动器
- 引擎的『重复输入』类错字（同一个词打两遍）**默认已关闭**（`config.json` 的 `Typo.RepeatWordPct=0`）

## 10. 常见问题（FAQ）

**1. 按 F9 没反应／悬浮条不出现。**
确认目标窗口是**前台**且输入框处于可输入状态；看 exe 同目录 `error.log` 中「热键已注册/热键注册失败」。
热键被别的软件占用时（实测：F12 被占用会记 `win32=1409`，程序仍能运行，只是该键失效），改 `config.json` 的 `Hotkeys` 键码后重启，或关掉占用该键的程序。

**2. 能开始，但字符出现在错误的位置（或没出现）。**
把 `Anchor.Method` 显式设为 `Caret` / `Uia` / `Mouse` 逐个试：`Caret` 适合记事本、传统 Win32 控件；
`Uia` 适合支持 UIA TextPattern 的程序；`Mouse` 最不精确但最通用。Chrome 类网页通常需要 `Uia` 或 `Mouse`。

**3. 插入符取不到怎么办？**
先用 F8「点击定位」：把鼠标点在目标输入框内，程序按点击位置定位，比窗口左上角兜底准得多。
若仍不准，把 `Behavior.BarOffsetX/Y` 调成你视觉上觉得合适的位置偏移。

**4. 目标窗口失焦（我去干别的了）。**
默认 `FocusLostPolicy=Pause`：暂停等待，你点回目标窗口后继续；改成 `Abort` 则中止并收尾。
代码与文档都以「不把文字打进错误窗口」为优先。

**5. 和我系统里的输入法（搜狗/微软拼音）冲突吗？**
不冲突：SimIme 不注册系统输入法，它只是模拟键盘/粘贴事件。但如果目标窗口此时**开着中文输入法**，
注入的字符可能被输入法再次拦截或组合；建议打之前把目标窗口切到英文/直接英文输入状态，
或用 `Inject.Method=Clipboard` 走剪贴板粘贴。

**6. 托盘提示文字或日志里的中文是乱码。**
程序以 UTF-8 写日志（`error.log`/`selftest.log`），用支持 UTF-8 的编辑器打开即可。
GUI 程序的 stdout 需要附着到父控制台，个别终端编码不同会显示乱码，改看日志文件最可靠。

**7. 结果是「打了字又删掉」很多次。**
那是拟人化错字机制：故意打错再退格改回，最后落屏一定等于原文（可用 `--selftest` 或
`tests\engine_tests.ps1` 校验）。想少一点：调小 `Engine.Typo` 各项，或把 `Enabled` 设为 `false`。

**8. 速度太慢/太快。**
调 `Engine.Rhythm`：`CharDelayMinMs`/`CharDelayMaxMs` 是每字延迟；`StartupDelayMs` 是你按 F9 后的准备时间；
`RestPause*`、`ThinkPause*` 是停顿。加速可把 `SpeedVariancePct` 调小。

**9. 结束后热键全都失灵了，是不是坏了？**
不是：结束后进入**静默待机**，程序主动注销了 F8/F9/F12，只留托盘可唤醒（这是设计目标）。
双击托盘图标唤醒后热键恢复。

**10. 想换台机器／绿色部署。**
整个目录拷走即可：`SimIme.exe` 已内嵌全部数据，`config.json`/`habits.dat` 可选（不放就用默认值/空习惯库）。

**11. 被杀软/EDR 报毒。**
本工具会模拟键盘输入、装全局钩子、读窗口信息，行为特征与按键精灵类工具相似，可能被拦截。
请加入白名单，或在受管机器上先咨询管理员。仓库只提供源码与构建脚本，可自行编译核对。

**12. 自检模式输出在哪？**
`--selftest "标题片段"` 会打印到控制台并写 `selftest.log`；`--printconfig` 会写 `config.json`。
两者都在 exe 同目录。

**13. 构建时报「无法清理 dist」（或删不掉 dist 里的 exe）。**
说明还有 SimIme 实例在跑：它持有单实例互斥体并把自己的 exe 映射在内存里，文件被占用就删不掉。
**先在托盘右键「退出 SimIme」**；退不出来就用任务管理器结束 `SimIme.exe`，然后重新构建。
（早期版本用「弃用互斥体」判断「已有实例」会误判、导致程序以为自己已在运行而直接退出——这个 bug 已修复。）

**14. 日志太大 / 我不想留痕。**
日志超过 2MB 会自动轮转为 `error.log.1`，删掉旧文件即可；彻底不要日志就把 `Behavior.LogEnabled` 改成 `false`
（注意：关掉之后锚定/悬浮条类问题就没法远程诊断了，这也是它现在默认开启的原因）。

**15. 提示「目标窗口可能以管理员权限运行」。**
这是 Windows 的 UIPI 规则（不是 bug）：用 `SimIme-Admin.exe` 启动主程序，或改走剪贴板兜底。
详见第 5 节，并可用 `_verify\typetest.exe` 自己做一次对照实验。

**16. 悬浮条的位置以前是错的，现在还对吗？**
以前把**客户区坐标当成屏幕坐标**用，悬浮条会跑到屏幕别处；这个问题已修（现在会区分并按窗口客户区换算，
日志里能同时看到 raw 与 converted 两套坐标）。若仍觉得位置不理想，调 `Behavior.BarOffsetX/Y`。

**17. 为什么我看不到拼音字母预览了？**
「字母预览」是**可选项，而且默认关闭**（`Inject.ImeSimulation = false`）：程序**直接上屏汉字**。
原因是实测在带联想/增量搜索的输入框里，退格可能清不掉已键入的字母，会**残留字母并弹出联想候选**，
甚至污染落屏文本；所以默认关掉，以「落屏文本 === 原文」为先。
确实想看那种效果：把 `Inject.ImeSimulation` 设为 `true`；一旦出现字母残留，改回 `false` 即可。

**18. 为什么 `--verify` 说「读不回内容」？**
它不会含糊其辞：三条回读路径（焦点控件 `WM_GETTEXT` → UIA → 剪贴板）都试过、仍拿不到「非空且不等于
窗口标题」的文本时，会明确写成 `三条路径都未取到有效文本`，而**不会**给你一个假的「不一致」。
Win11 记事本这类现代控件通常走 **UIA** 或**剪贴板**路径——日志里那行 `回读方式=` 会告诉你是哪一条。
如果目标压根没有文本接口（自绘编辑器、游戏内输入框、部分远程桌面窗口），三条都可能失败；
这时请以人工观察为准，或用 `--selftest` 看注入过程。

**19. 为什么 `--verify` 报过「退出码 6」，而不是说「不一致」？**
这正是**完整性护栏在干活**：实测中用户首次以普通身份运行时「我方=Low、目标=Medium」，Windows 会**静默丢弃**按键，
若继续比对只会得到假的「不一致」。护栏直接以 **6** 中止并提示改用 `SimIme-Admin.exe`；他提权重跑后立刻得到 `结果=一致`。
（完整链条见 4.1 里的 `error.log` 样本。）

**20. 为什么 `自检落屏.cmd` 要挨个试三个标题片段？**
实测证明必要：用户机器上记事本的标题是 `无标题 - Notepad`，片段 1「记事本」**永远不命中**，片段 2「Notepad」才命中。
如果你的编辑程序标题与这三个都不同（把鼠标悬停在任务栏图标上能看到标题），按 4.1 手敲换成你自己的片段即可。

**21. 为什么目标窗口里看不到拼音字母？**
这是**默认设计**：拼音只在悬浮条内组串，目标窗口只收到**词组级的汉字提交**（`Inject.PinyinInTarget = false`）。
原因很实际：实测把字母打进目标再退格，在部分程序里**清不干净、会残留字母并弹出联想候选**，
而本项目的最高优先级是「落屏文本 === 原文」。确实想看字母入目标的观感：把 `Inject.PinyinInTarget` 设为 `true`
（作者实测该路径在部分程序里仍可能残留字母，请自行权衡）。

**22. 为什么有时一个块只落 2 个字？**
粒度**取决于词表**：切分按最长匹配走 jieba 语料（约 12 万条 1~4 字词），词典外的搭配会被切细——
实测「天上有十二个星星」→ `天上 / 有 / 十二 / 个 / 星星`，所以会出现 1~2 字的块。缓冲层显示的拼音串仍是完整的；
想让某个搭配整块落下，有两条路：往词表里加词（数据改动），或者**让程序自己学会**（同一句多打几次，达到阈值后自动优先整块，见 1.3）。

**23. 为什么第一次打「天上有」还是被切成 `天上/有`？**
因为**自学习需要重复**：程序把你输入原文里的 2~4 字片段计数，某词组出现次数达到 `Engine.UserWordMinCount`
（默认 3）之后，切分才会优先把它当整块。所以第一次、第二次都可能仍是 `天上 / 有`（实测第 3 次后 `天上有` 就整块出现了）。
另外切分本身还有**按种子的随机抖动**（`Engine.RandomSeed=0` 时同一句不同次运行粒度可能不同）；
想稳定复现某一种粒度，就给 `Engine.RandomSeed` 一个非 0 值。详见 1.1 与 1.3。

**24. 为什么「更新词典」要重新构建？**
因为**内置词表是内嵌进 exe 的**（资源名 `SimIme.Assets.common_words.tsv`）：只把 `src\Assets\common_words.tsv` 换成新表，
正在运行的 exe 用的仍然是它内部那份旧表。所以 `更新词典.cmd` 拉完表必须再跑一次 `build.ps1`，让新词表被重新嵌进去。
若你只是想**补几条常用词、不想重建**：用主界面的「联网更新词典」按钮（或 `--updatedict`）——它写的是 exe 同目录的
**外部词表** `dict_extra.tsv`，启动时叠加进词组词典，**不需要重建**。

**25. 「联网更新词典」按钮和 `更新词典.cmd` 该用哪个？**
- **日常用按钮**（推荐）：写外部词表 `dict_extra.tsv`，点一下就生效，不重建、不需要管理员——适合补词、跟进上游。
- **`更新词典.cmd`** 只在你需要把**内置基线整体换代**时用（例如换一份新的 jieba 词表）：它会重写
  `src\Assets\common_words.tsv` 并重建 exe。必须在**项目目录的 dist** 里双击（需要源码与 PowerShell 7），且**先退出 SimIme**。默认 `-Mode auto`：pypinyin 源做**合并**（不丢词），jieba 源才替换。

**26. 「联网更新词典」下载的是通用词表吗？能替换内置词表吗？**
不是通用词表：它是 pypinyin 的**注音消歧词表**（`phrases_dict.json`），只收录读音需要特判的词。
实测那份 `dict_extra.tsv`（690963 字节 / 46111 行）里有 `十二个`/`我们`/`散步`/`你好`，
但**没有** `星星`/`太阳`/`明天`/`但是`/`生日快乐`/`天上有`（这些逐字读音就正确）。
因此它只能**补充**，不能**替换**内置表——内置表里这些常用词频次不低（`太阳(5044)`、`但是(28055)` 等），
硬替换会让词组切分退化。按钮的机制本来就是「叠加」（优先级：用户词组 > 外部词表 > 内置表）；
`更新词典.cmd` 默认也是 `-Mode auto`，对 pypinyin 源做**合并**，同样不丢词。

**27. 为什么第一次打某个词看不到多候选？**
候选优先给**真实同音词**（按频次，目标词第一）；真实同音词本来就少（例如 `xingxing` 能凑出 6 个真实词，而 `hongse` 只有 `红色` 是常用真词），
不够 `Inject.CandidateMax`（默认 6）时程序会用**同音字组合**补齐（`洪色/宏色/鸿色…`），所以你会看到「只有一个真词 + 几个像词的组合」。
另外候选来源是**三合一词表**：内置 12 万 + 外部 `dict_extra.tsv` + 你自己学到的用户词组——装过外部词表后候选会更丰富。

**28. 为什么确认候选的过程中，目标窗口里什么都没有？**
这是**设计如此**：确认过程只动悬浮条，不动目标窗口；只有当**一个组串缓冲全部确认完**，才把这段汉字**一次性**注入。
缓冲上限由 `Inject.BufferMaxPhrases`（默认 3 个词组）决定：设 `1` = 确认一段就落一段（最接近「逐词上屏」），调大 = 一口气落更多、等待更久。
日志里的「缓冲确认完毕，开始注入：第 X~Y 段」就是这一下。
